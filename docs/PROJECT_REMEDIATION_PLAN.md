# Easy Teach 整改与重新上线规划

更新时间：2026-08-29
适用范围：`easy-teach-dev` 本地代码库
当前策略：冻结服务器变更，完成本地整改和验收后整体重新部署

## 1. 目标

本轮整改首先交付一条可信、可恢复、可测试的文字 AI 主链路：

1. 教师创建项目并进入唯一的需求共创工作区。
2. 历史对话和 TeachingBrief 能正确加载、编辑和持久化。
3. DeepSeek 成功、失败、超时和格式异常都有明确状态，不再把系统错误伪装成正常追问。
4. 教师确认需求后，由 DeepSeek 生成可用教学蓝图和分格式内容规格，再生成 PPTX、DOCX、PDF 和互动 HTML。
5. 所有关键步骤有自动化测试、可观察日志和清晰的失败恢复方式。

本轮暂不恢复本地视频模型、语音模型和本地大模型推理。视频能力继续关闭，不作为文字版重新上线的阻塞项。

## 2. 整改原则

- 服务器冻结：整改期间不修改 `/opt/easy-teach`、数据库、容器或线上 `.env`。
- 单一真实入口：删除或改造演示页面，避免 mock 页面和真实页面并存。
- 数据库为准：页面刷新、重新登录和容器重启后，项目状态必须能够完整恢复。
- 错误必须可见：模型错误、接口错误和业务信息不足必须使用不同状态表达。
- AI 输出必须验证：所有模型 JSON 先归一化和校验，再进入数据库与生成流程。
- 模型负责内容，渲染器负责文件：教学叙事、章节内容、讲解、例题、互动题和答案由模型生成；程序只负责排版、文件封装、安全过滤和一致性校验。
- 禁止模型直接生成可执行文件代码：模型只返回受约束的结构化 JSON，不直接输出任意 HTML、JavaScript、DOCX 或 PPTX 二进制内容。
- 模板降级要透明：使用确定性模板时必须明确标记，不能伪装成 AI 生成。
- 先修主链路，再扩展能力：文字需求共创通过后，再处理蓝图质量、资料解析和视频能力。

## 4. 阶段规划

### 阶段 A：统一真实需求共创入口

目标：项目创建、继续项目、历史对话和需求表单使用同一套真实数据链路。

任务：

- 移除 `RequirementsView.vue` 对 `frontend/src/mocks` 的依赖。
- 将侧边栏“需求共创”改为真实项目/会话入口。
- 无活动项目时进入项目创建页；有活动项目时进入 `/chat/:sessionId`。
- 使用 `storeToRefs()` 或计算属性订阅 Pinia 的 `messages`、`brief`、`projectId`。
- 会话加载时正确恢复 text、question、confirm 和 error 类型消息。
- 明确页面状态：首次进入、加载中、空会话、发送中、失败、重试、已确认。
- 对已归档、会话不存在、权限不匹配等情况提供可恢复导航。

验收标准：

- 新建项目后发送消息，刷新页面仍能看到完整对话。
- 从工作台点击“继续”后，历史消息和最新 TeachingBrief 同时出现。
- 页面不再显示固定“浮力”示例数据。
- 全局搜索确认生产视图不再导入 `frontend/src/mocks`。
- `/requirements` 不再是无状态演示页。

### 阶段 B：修复 DeepSeek 对话与错误协议

目标：模型响应可靠落库，任何失败都能被用户和日志准确识别。

任务：

- 对模型返回的 `null`、空字符串、错误类型和缺失字段做统一归一化。
- 为 DeepSeek 结果增加独立适配层，不让原始响应直接进入业务模型。
- 扩充结构化提示词，覆盖课程主题、教学目标、授课对象、课时、知识点、逻辑顺序、教学重点、教学难点、产出类型和互动思路。
- 将同步 OpenAI 客户端替换为异步调用，或放入受控线程，避免阻塞 FastAPI 事件循环。
- 为模型调用设置连接超时、读取超时、有限重试和总时限。
- 增加 `error` SSE 事件，区分模型错误、解析错误、网络错误和业务缺失信息。
- SSE 完成后同步事件中的 brief，或重新请求最新 brief。
- 仅将有业务意义的对话传给模型，排除“正在分析”“服务不可用”等系统状态消息。
- 模型失败时不覆盖已有有效字段，不把错误文字写入业务 `missing_info`。
- 每轮对话更新项目 `updated_at`，保证工作台状态准确。

验收标准：

- 模型字段为 `null` 时不会产生 500、静默失败或错误草稿。
- 模型不可用时页面明确显示“AI 服务失败”，并提供重试入口。
- 信息不足时显示正常追问，且与系统错误视觉和协议上可区分。
- DeepSeek 成功后右侧 TeachingBrief 无需刷新即可更新。
- 连续多轮对话不会被之前的错误消息污染。
- 同时发起多条不同会话请求时，API 不因同步模型调用整体阻塞。

### 阶段 C：重构 TeachingBrief 确认逻辑

目标：教师能看懂、修改、保存并确认一份稳定的教学需求单。

任务：

- 明确“课程主题”和“教学目标”为不同字段，避免语义混用。
- 将必填字段、可选字段和 AI 建议字段分组展示。
- 统一前端和后端字段名、产出类型枚举及课时单位。
- 保存修改后立即返回并显示最新版本号和完整性状态。
- 确认前展示具体缺失字段，不只返回笼统失败。
- 已确认 brief 再修改时创建新草稿版本，不覆盖已确认版本。
- 增加版本冲突提示和刷新恢复流程。
- 明确项目状态：需求收集中、待确认、已确认、蓝图已生成、成果已生成。

验收标准：

- 教师手动修改所有字段后，刷新页面数据不丢失。
- 缺失字段与“确认需求”按钮状态始终一致。
- 两个页面同时修改同一 brief 时，旧版本提交得到明确冲突提示。
- 已确认版本不可被静默覆盖。

### 阶段 D：让蓝图生成真正使用 AI

目标：DeepSeek 根据已确认需求和证据生成结构化蓝图，并以该蓝图作为全部成果内容生成的唯一事实来源；确定性模板只作为显式降级。

任务：

- 将已确认 TeachingBrief、资料证据和 RAG 结果组成统一生成上下文。
- 使用 DeepSeek 生成严格的 `CoursewarePlanSpec` JSON。
- 蓝图必须包含教学叙事、知识点依赖、讲解深度、例题与案例、课堂活动、评价方式和引用证据，不能只生成标题列表。
- 对 slides、lesson_sections、interactions、时长总和和引用证据做后端校验。
- 对可修复格式错误执行一次受控纠错，禁止无限重试。
- 模型不可用时允许选择“稍后重试”或“使用基础模板”。
- 模板生成结果标记 `generation_mode=template`，AI 结果标记 `generation_mode=ai`。
- 保留模板编译器作为稳定兜底和离线测试基线。
- 删除或合并重复且未接入的 `ai/intent`、`ai/fusion`、`gen/parse` 实现，避免多套逻辑漂移。

验收标准：

- 不同学科、年级和教学目标生成的蓝图结构与内容有明显差异。
- 蓝图 JSON 始终通过 Pydantic 校验，失败时不会产生半成品记录。
- 课时环节总时长与 TeachingBrief 基本一致。
- AI 与模板降级在数据库、日志和页面上可区分。
- 相同 brief 的重复请求具备幂等行为，不重复扣费或创建冲突版本。

### 阶段 E：AI 成果内容生成与可靠导出

目标：DeepSeek 基于同一份已验证蓝图生成分格式内容规格，确定性渲染器再将规格安全、稳定地输出为 PPTX、DOCX、PDF 和互动 HTML。

任务：

- 定义可版本化的 `SlideDeckSpec`、`LessonPlanSpec`、`PrintableDocumentSpec` 和 `InteractionSpec`，全部使用 Pydantic 严格校验。
- DeepSeek 生成 PPTX 的逐页标题、教学叙事、要点、例题、图示建议、课堂活动和真实演讲者备注；`python-pptx` 只负责主题、布局、分页和文件写入。
- DeepSeek 生成 DOCX 的完整教案正文，包括目标、学情、重点难点、时间分配、教师活动、学生活动、板书、评价和课后任务；`python-docx` 只负责样式、表格、分页和文件写入。
- PDF 复用经过验证的可打印文档规格，由受控 HTML/Office 转换链生成，不让模型直接生成 PDF；PDF 与 DOCX 内容版本保持可追踪关联。
- DeepSeek 生成 HTML 互动题的题干、选项、正确答案、答案组、解析、提示、计分规则和反馈文案；固定互动引擎负责判题、计分、重置、匹配、分类和排序。
- 模型不得返回或执行任意 HTML/JavaScript；所有文本进入模板前转义，JSON 使用安全序列化并设置 CSP。
- 支持教师在导出前预览和编辑分格式内容，并能只重新生成某一页、某一章节或某一道互动题。
- 记录模型、提示词版本、输入蓝图版本、token 用量、生成模式和人工修改记录，保证成果可追踪、可复现。
- 将四种格式拆为独立幂等任务，分别记录 `pending/processing/completed/failed`，允许部分成功、单独重试和取消。
- 合并初次生成与成果导出的重复链路，统一成果记录、版本、任务、文件和下载接口。
- 修复 `pending` 超时恢复、前后端超时一致性、重复提交、孤立文件清理和失败补偿事务。
- 下载接口返回统一错误协议；前端正确解析 Blob 错误，并显示格式、任务 ID 和可执行的重试操作。
- 拆分需求版本与成果版本字段，不再复用 `current_version_id` 表达两种对象。
- 为图片/PDF 内图片选择真实支持视觉输入的模型供应商；未配置时明确关闭视觉解析。
- 删除硬编码假 API Key 和模拟“识别成功”返回。
- 视频能力继续保持关闭，并在前端隐藏不可用入口。
- 知识库未建立索引时明确显示“未索引”，不暗示已使用 RAG。
- 补充任务失败、重试、恢复和重复提交的页面状态。

验收标准：

- 四类成果的标题、知识点、顺序和互动内容与同一蓝图一致，同时符合各自媒介的表达特点，不是相同文本的机械复制。
- 两组不同学科的真实需求生成结果在教学叙事、案例、活动和评价方式上有可解释差异，且不存在占位文本。
- PPTX 备注位于真实演讲者备注区；DOCX/PDF 分页稳定；HTML 能完成判题、计分、解析和重置。
- 不支持的图片或视频能力返回明确的能力不可用状态。
- 任一生成任务失败后可以安全重试，不产生重复成果或错误版本。
- PPTX、DOCX、PDF 和 HTML 均能打开，且无明显空白、乱码、内容越界或脚本注入风险。

### 阶段 F：测试、可观察性与安全门槛

目标：用业务结果而不是 HTTP 状态码判断系统是否可上线。

任务：

- 为 DeepSeek 适配层增加 `null`、缺字段、非法 JSON、超时、限流和 5xx 单元测试。
- 为完整聊天、brief 保存、确认、继续项目和蓝图生成增加 API 集成测试。
- 增加前端组件测试，覆盖 Pinia 引用更新和 SSE brief 同步。
- 增加 Playwright 端到端测试：注册、建项目、聊天、刷新、继续、修改、确认、生成蓝图、生成四类成果并实际下载。
- 下载后解析 PPTX/DOCX/PDF/HTML，验证文件签名、核心内容、版本关联、正确 MIME 和非空页面；不能只断言接口返回 200。
- 为互动 HTML 增加浏览器测试，覆盖正确答案、错误答案、匹配、分类、排序、计分、解析、重置和恶意文本转义。
- 建立至少 20 条教学需求固定样本，覆盖文理科、不同年级和中英文输入。
- 日志增加 request_id、user_id、project_id、session_id、模型耗时、模型状态和 token 用量；禁止记录 API Key。
- 为注册、登录、聊天和生成接口增加限流及用户额度控制。
- 正式重新上线前配置域名和 HTTPS。
- 轮换曾在沟通记录中出现过的 DeepSeek API Key。

验收标准：

- 自动化测试能复现并阻止 R-001 至 R-010 回归。
- 20 条固定样本中，结构化解析成功率达到 95% 以上。
- 模型故障注入时，前端均显示明确错误且数据库不产生损坏状态。
- 日志可以根据一次用户操作追踪完整请求链路。
- 未授权用户无法访问他人的项目、会话、成果和下载文件。
