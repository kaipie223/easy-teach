# 队友问题对照与剩余整改计划

更新时间：2026-08-30
对照来源：`项目调优建议.docx`、`issues-and-solutions.md`
判断基线：当前本地工作区；服务器继续冻结

## 1. 本轮产品决策

1. 取消管理员上传和维护公共知识库的功能。
2. 知识库改为教师私有资源，每位教师只能管理和检索自己的文档。
3. 管理员账号不再默认拥有教师工作流和跨用户项目修改权限。
4. 视频与视觉模型继续关闭，不进入本轮上线范围。

## 3. 新架构：教师私有知识库

### 数据与权限

- `knowledge_documents.owner_id` 改为非空，并将唯一约束纳入 `owner_id`。
- 教师只能列出、上传、更新、删除、索引和检索自己的知识库文档。
- RAG 检索必须同时过滤 `owner_id`，不能先做全局检索再仅靠前端过滤。
- Chroma 使用教师命名空间或独立 collection，例如 `knowledge_user_<user_id>`。
- 文件保存到共享数据卷下的用户目录，例如 `/app/data/knowledge/<user_id>/...`。
- 项目生成只使用项目拥有者的私有知识库和当前项目资料。
- 管理员不拥有知识库上传、索引、搜索或读取教师正文的接口权限。

### 前端

- 从管理员侧边栏和管理员工作台删除“知识库管理”。
- 为教师增加“我的知识库”，保留导入、启停、删除、索引和检索验证。
- 管理员布局只显示管理员工作台、账号退出和后续真正需要的运营功能。
- 普通教师不能进入管理员工作台；管理员也不复用教师项目工作流。

### 旧数据处理

- 重新上线前导出当前公共知识库文档清单。
- 有明确上传者的文档迁移给对应教师；无法确认归属的文档默认归档，不自动公开给所有教师。
- 重建每位教师的索引，完成后再删除旧全局 collection。

## 4. 执行计划

### 阶段 1：权限边界和私有知识库（P0，2-3 天）

状态：已完成（2026-08-30）。数据库迁移、教师级文件/索引/RAG 隔离、管理员入口移除、跨账号权限测试均已落地。

1. 新增迁移：知识库 owner 非空、用户级唯一约束和索引命名空间。
2. 将知识库 CRUD、索引和搜索从 `require_admin` 改为教师 owner 校验。
3. 将 RAG 上下文绑定当前用户，禁止跨用户命中。
4. 移除管理员知识库入口和教师业务导航；收紧管理员跨项目 ownership 绕过。
5. 补两名教师互相访问文档、证据和搜索结果的越权测试。

验收：教师 A 无法通过列表、ID、搜索或生成上下文看到教师 B 的任何知识片段；管理员不能上传公共文档。

### 阶段 2：上线前安全与部署（P0，3-4 天）

状态：已完成（2026-08-30）。代码加固及已暴露 DeepSeek Key 的人工撤销和轮换均已完成。

1. 删除匿名生产链路，聊天、会话、上传、语音、生成和任务全部要求登录。
2. 增加用户/IP 限流、每日模型额度、任务并发和存储配额。
3. 上传与语音改为流式落盘和大小限制；清理失败临时文件。
4. 生产 Compose 显式设置 `TASK_QUEUE_EAGER=false`、`UPLOAD_DIR=/app/data/uploads`、输出目录和私有知识库目录。
5. 增加生产配置自检：默认 JWT、宽泛 CORS、eager 模式直接拒绝启动。
6. 轮换 DeepSeek Key，并移出普通 `.env`/Compose 展开输出。

验收：未登录请求不能创建或读取业务数据；生产 API/worker 可读取同一文件；敏感配置不会进入日志。

### 阶段 3：数据一致性与并发（P1，2-3 天）

状态：已完成（2026-08-30）。迁移 `0010`、项目版本锁、知识点结构保留、legacy 多模态关闭、RAG 线程池和分布式索引切换均已落地。

1. 为 Brief、CoursewarePlan 和 ArtifactVersion 增加项目级唯一版本约束。
2. 使用行锁或冲突重试创建新版本，并增加并发测试。
3. 修复 Brief 知识点编辑，保留稳定 ID、要点、案例、难度和预计时长。
4. 删除 legacy 图片/视频解析入口，或统一为有类型的“能力不可用”结果。
5. 将 RAG 放入线程池/worker，索引重建使用 Redis/数据库分布式锁和临时 collection 原子切换。

验收：并发修改不产生重复版本；教师编辑 Brief 不丢字段；索引重建期间旧索引仍可查询。

验证：现有预览数据库已成功升级到 `0010`；4 个并发写入得到连续版本 1-4；后端 57 项测试、Ruff 和前端生产构建通过。

### 阶段 4：生成质量与编辑体验（P1，3-5 天）

状态：已完成（2026-08-31）。独立分格式规格、可编辑蓝图、AI 局部重生成、动态追问、双模型内容审校、确定性互动归一化和工作台修订均已落地；最终版 20 条跨学科真实 DeepSeek 样本结构与人工质量均 20/20 通过，私有 RAG 证据链及 Office/WPS 人工检查已通过。

1. 合并重复 intent/fusion 实现，提示词版本化；根据课程复杂度动态追问。
2. 为 PPTX、DOCX、PDF、HTML 定义独立内容规格，并允许按页、章节、题目局部 AI 重生成。
3. 将蓝图页改为可编辑预览，保存后创建新蓝图/成果版本而不是覆盖。
4. 用至少 20 条跨学科样本评价内容完整性、差异度、事实一致性和互动可用性。
5. 对 PPTist 做独立技术验证，只在排版质量显著优于现有渲染器且部署成本可接受时引入。
6. 完成工作台项目名编辑、隐藏内部 ID 和操作列对齐。

验收：两组不同课程的四类成果内容和表达方式明显不同；教师可以安全修改并回滚；无占位文本和空洞章节。

### 阶段 5：发布验收（P0，2-3 天）

状态：自动化与本地基础设施验收已完成（2026-08-31）。后端 98 项测试、Ruff、前端生产构建、Playwright 四格式下载、全新数据库迁移、生产 Compose 配置、20 条真实 DeepSeek 质量矩阵及真实 Redis/Celery worker 中断恢复均通过；剩余项均为发布凭证或目标环境人工验收。

1. Playwright 覆盖登录、私有知识库、需求共创、确认、AI 蓝图、修订、四格式生成和实际下载。
2. 解析下载文件并验证 PPT 备注、DOCX/PDF 正文、HTML 四类互动及恶意文本转义。
3. 在真实 Redis/Celery 下演练任务失败、重试、worker 崩溃和 stale 恢复。
4. Office/WPS 人工打开，完成 HTTPS、备份、迁移演练和回滚演练。

验收：所有 P0/P1 自动化与人工门槛通过后，才重新部署服务器。

## 5. 建议顺序

先做阶段 1 和阶段 2。教师私有知识库会改变数据模型、检索命名空间、权限和部署目录，如果先继续优化生成质量，后续还要重新改一遍 RAG 上下文和测试。
